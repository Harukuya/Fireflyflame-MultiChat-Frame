# 框架样例资料

这里是可直接编辑的 UTF-8 明文资料，不含原插件的剧情、风格文本、私人账号或印象。图书馆读书、周末散步和林舟都是原创虚构样例，用来演示结构，**不代表角色与真实账号发生过这些事**。使用前请替换或清空。

本目录包含 2 个知识场景、1 条可检索的身份认知、1 个人物和 2 条风格样例。样例默认只做字词检索，不需要生成向量。资料由 `DataSource` 加载，宿主创建 `Knowledge`、`People`、`Style` 实例；编辑后需由宿主重载这些实例，或重启应用。

## 文件与清空方法

| 文件 | 用途 | 怎样清空 |
| --- | --- | --- |
| `knowledge/kb.json` | 可检索的背景资料、角色知情范围 | 把 `missions`、`keys`、`anchors`、`self` 一起改成 `[]`；也可用 `{}` |
| `people.json` | 对设定人物的认知与代表性说话内容 | 保留 `{"people": []}` |
| `style.json` | 说话风格参考，不是当前发生的事 | 保留 `{"samples": [], "voice": []}` |
| `self/她对自己的认知.md` | 每轮基础身份认知，文件名为兼容资源路径保留 | 清空正文；本文件也允许不存在 |

按样例文件加载时，三个 JSON 文件需要保留并且语法正确，不能写注释或末尾多余逗号。知识、人物和风格三份都清空时，对话及动态记忆仍能使用，但不会附带这三种预置参考。也可通过构造器的 `data=` 参数注入字典。加载失败会抛出异常，宿主应先成功加载全部新实例，再替换当前实例，避免留下半新半旧的资料。

## 知识资料 `knowledge/kb.json`

`missions` 是场景数组，`keys` 是检索入口数组。一个场景可以对应多个入口。`anchors` 是触发联想的人名、地点或主题，`self` 放可检索的自我认知。

本样例使用的字段如下：

- `missions[].key`：场景标识和显示标题。改为有意义且不重复的名字。
- `missions[].at`：场景之间的排序数字，不是时间戳；没有确定先后可省略。`1`、`2` 只代表样例顺序。
- `missions[].her`：角色知道的内容，每项至少有 `text`。这里的文字会交给角色；请写清楚哪些是设定、听说、虚构示例。不要把搜索关键词当作正文。
- `missions[].words`、`recall`：进阶的原话与分段回忆，本样例保留空数组；简单资料不必启用。
- `keys[].text`：匹配用的关键词或自然语言。它只参与检索，通常不会直接作为正文给角色。
- `keys[].kind`：本样例只用 `her`（场景内容）和 `self`（自我认知）。
- `keys[].cls`：本样例为 `mine`，表示角色可据此回答。别用 `mine` 装入角色不该知道的秘密。
- `keys[].m`：场景在 `missions` 数组的位置，**从 0 开始**；`self` 入口固定用 `-1`。
- `keys[].i`：该场景 `her` 内的位置，或 `self` 数组内的位置，也从 0 开始。删除、移动条目时同步改索引。
- `self[].text`：被检索到时带入的身份认知。它和 Markdown 中每轮加载的身份说明用途不同，不必重复填写很多内容。

示例查询：`图书馆的阅读角是什么样的？`、`周末沿河边散步时会注意什么？`、`小伴，你是谁？`。字词检索依赖词面重合，不能保证同义改写、隐喻等语义检索效果。

## 人物资料 `people.json`

每个人物至少保留样例中的字段：`name`（显示名）、`names`（匹配名字和别名的数组）、`pron`（代词）、`tier`、`two`（描述数组）、`quotes`（语句数组）。

`tier` 用 `other` 表示普通人物，`close` 表示亲近人物。它只控制人物卡最多带 3/5 句以及模仿提示，不会设置 QQ 用户的动态亲密度。没有向量时按文件顺序取前几句。`quotes[].when` 可写原句出现的语境；不需要原话时保留 `quotes: []`。一轮最多取最先被提及的 2 个人物。请不要用空字符串作为别名。

## 风格资料 `style.json`

每个 `samples` 条目包含独立 `id`、`source`、`context` 和 `reply`（多条字符串）。明确写出这是虚构范例；`source` 推荐写来源名称，`context` 说明当时语境。参考的是语气、节奏和表达方式，不能当作本轮事实或用户历史。

默认最多取 4 个样例；无向量时根据字词相似度选择。风格样例不设相关性门槛，因此只有这 2 条时可能每轮都见到它们，请替换成适合你角色、不会误导事实判断的代表性样例。`voice` 是可选的短句语义参考，没有匹配向量时不启用；本框架保持为空。

## 自我认知 Markdown

`## 给角色的` 与 `## 出处` 之间是给模型的内容；`### 小标题` 会变成段落标题。`## 给她的` 也兼容。角色姓名及基础提示词还要在宿主传给 `profile.configure()` 的配置和 `prompts/` 中同步修改，改这份资料不会替换其他配置。

**配置中改名不会自动改写样例资料。** 例如把角色名改成“小夏”时，应同时改掉本目录 JSON、Markdown 中的“小伴”和对应 `anchors`、`keys`，或直接清空样例。框架不会对任意正文做全局替换，以免误改人名、引文和已经发生的真实记录。

## 可选向量

当前样例的 `model: null`、`format: "lexical"` 表示无预计算向量。知识与风格会按字词检索，人物按名字匹配。不要填假向量，也不要仅改 `model` 标签来冒充兼容。

框架保留了原有的可选本地向量接口：只有模型标识、编码格式和对应向量都匹配时才使用。当前接口要求 `multichat/embed.py` 定义的 `MODEL_ID`（`jinaai/jina-embeddings-v2-base-zh`）和 `VECTOR_FORMAT`（`wasm-single`），向量必须用同一实际模型、同样的预处理、维度与量化方式生成。没有通用的“随便放一个模型向量就能用”的兼容保证，本样例也不包含生成工具或模型权重。知识库缺少或不匹配的向量会整体退回字面检索。
